# Build Log

Append-only ledger of every Stories build that left someone's machine.

**If you are about to build, read the latest entry first.** The "version" column tells you what number was last claimed. Pick the next one (e.g. last was `0.9.10-6` → you build `0.9.10-7`), bump `package.json`, then build. Append a new row when your build is done. The `make:*` scripts will refuse to build a version that already appears in this log (enforced by `scripts/guard-version-not-built.js` via `built/<version>` git tags).

Note: `0.9.10-10` adds two features — transcript suffix (user-defined word/phrase appended to final transcriptions) and media file import (transcribe existing audio/video files) — plus the suffix-editor UI fixes. Signed with the Pixelspace cert, not notarized.

Note: `0.9.10-10` was **rebuilt in place on 2026-07-20** (same version number, new bits, tag and release asset replaced) to ship two corrections found while dogfooding:
1. **Media import no longer requires ffmpeg.** The first `0.9.10-10` cut required a system `ffmpeg` binary, which macOS does not ship and GUI apps cannot see on `PATH` even when Homebrew installed it — so import failed for everyone. Conversion now happens entirely in the renderer: Chromium decodes the container (video picture discarded), the audio is downmixed to 16 kHz mono, and a vendored dependency-free MP3 encoder (`@breezystack/lamejs`, LGPL, audited: zero network calls) produces the upload. Nothing to install.
2. **Silent recording no longer hangs the main window.** Recording a fully-silent clip from the widget (mic far/muted) left the main window stuck on "Transcribing..." forever, because the widget's empty-audio branch reset itself but never told the main window to clear its spinner. Fixed by sending the same `transcription_completed` sync the success/error branches already use. Verified live via console capture of both renderers.

| 0.9.10-11 | internal (signed + notarized) | Arturo | 2026-07-29 | fix/recording-reliability | [`built/0.9.10-11`](../../../../tree/built/0.9.10-11) | [GitHub release](https://github.com/pixelspace-studio/stories-app/releases/tag/built/0.9.10-11) |

Note: `0.9.10-11` is a recording-reliability build. It fixes four defects found while diagnosing a report of a transcription that contained only the single word "Pixelspace" (a user's dictionary entry) after several minutes of speech:

1. **The record shortcut could be silently swallowed.** For 3 s after a transcription completes, a shortcut press is interpreted as "open Smart Transforms". That branch returned before the ensure-widget-visible code, and the widget's dropdown opener no-ops when presets/id are missing — so with auto-hide on, the press produced no visible effect and started no recording. Users spoke for minutes believing they were recording; the press they meant as "stop" then started a short recording of ambient noise. Now the transform interpretation requires the widget to be visible with the 3-2-1 countdown on screen; otherwise the press falls through to record, so a press always has a visible effect.
2. **An orphaned AudioWorklet doubled every fluid chunk.** `stop()` cleaned up via instance fields *after* its awaits, so a `start()` arriving in that window had its fresh audio graph clobbered while the old `AudioContext` kept running with a live worklet. One escaped on 2026-07-27 and fed every later recording a second copy of the mic signal — chunks carried ~32 000 samples/s under a 16 kHz WAV header (verified byte-exact against the audio Gemini received). `stop()` now tears down the session graph captured as locals before any await, and a context audit runs after every stop and before every start, closing and logging anything that escaped. Restarting the app was the interim mitigation.
3. **The widget never released the microphone.** The normal stop path stopped the `MediaRecorder` but never called `track.stop()` — only the cancel path did. Every recording leaked a live mic stream: the macOS mic indicator stayed on permanently, and a leaked live stream is what gave the orphaned worklet real audio to capture. Streams are now registered on open and released on stop, with a safety sweep in the widget's terminal inactive state. (macOS remembers mic permission per app; releasing tracks never re-prompts.)
4. **Gemini hallucinated the custom dictionary on unintelligible audio.** With no speech to transcribe, the model latched onto the only text in its prompt — the vocabulary hint — and returned dictionary words as the "transcript", which the app saved as a success. The prompt now instructs Gemini to return `[NO_SPEECH]` when it cannot resolve the audio into words; that response maps to empty text and `/api/transcribe` reports an explicit "No speech was detected" error instead of saving hallucinated or empty output. Validated against the incident audio before landing: 8/8 sentinel on the garbage recording, 0 false positives on real-speech controls. Whisper is deliberately untouched — its `prompt` parameter is a style primer, not an instruction channel, so instruction text there would itself be echoed as a hallucination.

Also adds **live voice bars to the widget** beside the timer, driven by the real recording stream: if they do not move while you speak, the mic is not being heard. That is the early warning for the whole class of silent-non-recording failures. Recording states widen 130 → 152 px to fit them.

Not live-tested before packaging (built straight from `fix/recording-reliability` at Arturo's request); all five touched files passed syntax checks and the sentinel was validated end-to-end through the modified backend. Note: `backend/app.py` still carries a stale `VERSION = "0.9.8"` constant — `scripts/version.js` cannot express the `-NN` suffix, so `package.json` remains the single source of truth for the build number.

| 0.9.10-12 | internal (signed + notarized) | Arturo | 2026-07-29 | fix/recording-reliability | [`built/0.9.10-12`](../../../../tree/built/0.9.10-12) | [GitHub release](https://github.com/pixelspace-studio/stories-app/releases/tag/built/0.9.10-12) |

Note: `0.9.10-12` polishes `0.9.10-11` from a dogfooding session and closes the diagnosability gap that made the bugs in `-11` expensive to find. **In hindsight this should have been a rebuild in place of `0.9.10-11`, not a new number** — it is the same body of work, the way `0.9.10-10` was rebuilt in place on 2026-07-20. Kept as `-12` because `-11` had already been distributed and installed.

Verified live in the `0.9.10-11` build before this one was cut: mic tracks released (0 live tracks while idle, previously 1 leaked permanently), 0 running `AudioContext`s after four recordings (previously 97 created / 1 orphaned), and four consecutive stress-test recordings captured at 1.00x sample rate with durations matching wall clock to the second.

Changes:
1. **Voice bars finished.** Bars turn accent pink past the same 0.7 band threshold the main window's visualizer uses; 2px more separation before the cancel button (recording states 152 → 154 px so the row does not lose those pixels); and stopping a recording leaves the bars at rest — minimum height, gray, still — instead of removing them, which left the widget window at its recording width with visibly empty space. They give their width back only when the row is genuinely rebuilt (compact, or the transform layout).
2. **Renderer → `main.log` bridge.** `main.log` only ever captured the main process console, so every widget and main-window renderer log lived in DevTools alone — useless when a user reports a problem. New `renderer-log` IPC channel + `window.electronAPI.logToMain()`. Anomalies only, on purpose: `main.log` is valuable because it holds decisions and warnings, not narration.
3. **Capture-rate self-check.** The fluid manager counts samples actually delivered by the worklet and compares them against the `AudioContext`'s reported rate, reporting a >10% deviation once per session with both numbers. The 2026-07-27 orphan-worklet bug ran at double rate for two days with no symptom but degraded transcripts and had to be reconstructed from chunk byte sizes afterwards; this names it on the first chunk.
4. **`main.log` keeps one rotation** (`main.log.1`). A user restarts before reporting, which is exactly when the log explaining the problem was being destroyed — the story lost to a swallowed shortcut press could not be confirmed afterwards for this reason.
